# 部署运维手册

面向生产环境的部署、加固与运维指南。本项目为**轻量化单体**：一个 NestJS 后端进程 + 一份 Vue3 静态前端 + 单文件 SQLite，无外部中间件强依赖，可单机 Docker/systemd 直接跑起来。

---

## 一、部署形态

```
                          ┌───────────── Nginx（TLS 终止 + 反向代理 + 静态托管）─────────────┐
   Internet / 内网  ─────▶│  /            → 前端静态 dist/                                     │
                          │  /admin/api/  → 127.0.0.1:8080   (建议 IP 白名单)                  │
                          │  /mcp         → 127.0.0.1:8080   (SSE：关闭 buffering，长超时)     │
                          │  /healthz,/metrics → 127.0.0.1:8080 (仅内网/本机，无鉴权)           │
                          └───────────────────────────────┬───────────────────────────────────┘
                                                           ▼
                                          NestJS 网关（node dist/main.js，仅监听 127.0.0.1:8080）
                                                           │
                                                           ▼
                                          SQLite 单文件 data/gateway.db（WAL）+ data/backup/
```

关键原则：**后端只监听 `127.0.0.1`**，一切外部流量经 Nginx；TLS 在 Nginx 终止；`/healthz`、`/metrics` 无鉴权，必须在 Nginx 层限制来源。

## 二、生产构建

```bash
# 后端：编译到 dist/
cd backend
npm ci                      # 干净安装（better-sqlite3 会编译原生模块）
npm run build               # → backend/dist/main.js

# 前端：打包到 dist/（hash 路由，纯静态）
cd ../frontend
npm ci
npm run build               # → frontend/dist/
```

> `better-sqlite3` 是原生模块。构建机需具备编译工具链：macOS 装 Xcode Command Line Tools；Debian/Ubuntu `apt install -y build-essential python3`；Alpine `apk add python3 make g++`。Node 版本 **≥ 20.18.1**。

## 三、环境变量与密钥

后端直接读取**进程环境变量**（无 dotenv 自动加载）。模板见 [`backend/.env.example`](../backend/.env.example)。生产最少必须设置：

```bash
# 生成强随机密钥
openssl rand -hex 32        # → MGW_SECRET（AES-256-GCM 主密钥，加密上游凭据）
openssl rand -hex 24        # → ADMIN_TOKEN（管理后台令牌）

export NODE_ENV=production
export MGW_HOST=127.0.0.1
export MGW_PORT=8080
export MGW_PUBLIC_ORIGIN=https://mcp-gw.example.com   # 对外 HTTPS 基址
export MGW_SECRET=<上面生成>
export ADMIN_TOKEN=<上面生成>
export MGW_DB_SYNCHRONIZE=0                           # 关闭自动建表，改用 migrations
export MGW_OUTBOUND_ALLOWED_CIDRS=10.0.0.0/8,127.0.0.1/32   # 按实际上游网段最小化
```

**密钥管理**：优先用 `MGW_SECRET_FILE` / `ADMIN_TOKEN_FILE` 指向 secret 挂载文件（Docker secrets / K8s Secret / Vault Agent），避免密钥出现在进程列表或镜像层。

> ⚠️ `MGW_SECRET` 一旦变更，**历史加密的上游凭据将无法解密**，需在后台重新录入各上游的 Header/Env。请在初次上线时即固定并异地备份该密钥。

## 四、建表方式：synchronize → migrations

MVP 默认 `MGW_DB_SYNCHRONIZE=1`，由 TypeORM 依据实体自动建表，零迁移上手。**生产建议关闭自动建表**，改用受控迁移：

```bash
cd backend
# 1) 生成初始迁移（对空库运行会生成完整 schema；文件写入 src/database/migrations/）
npm run typeorm -- migration:generate src/database/migrations/Init -d src/database/data-source.ts

# 2) 执行迁移
npm run migration:run
```

- **全新部署**：设 `MGW_DB_SYNCHRONIZE=0` → `migration:generate Init` → `migration:run` → 启动。
- **已用 synchronize 跑起来的库**：先 `migration:generate` 得到与现状一致的 schema，再手动清空生成文件里已存在的建表语句（作为 baseline），或用 TypeORM 的 `migrations` 表打基线，避免重复建表。
- 后续 schema 演进：改实体 → `migration:generate <Name>` → review 生成的 SQL → `migration:run`。

`src/database/data-source.ts` 是 CLI 与运行时共用的同一份连接配置，杜绝「CLI 建的表和运行时不一致」。

## 五、进程守护（systemd）

`/etc/systemd/system/mcp-gateway.service`：

```ini
[Unit]
Description=MCP Gateway (NestJS)
After=network.target

[Service]
Type=simple
User=mcpgw
WorkingDirectory=/opt/mcp-gateway/backend
EnvironmentFile=/etc/mcp-gateway.env          # 直接兼容 .env.example 格式
ExecStart=/usr/bin/node dist/main.js
Restart=always
RestartSec=3
# 加固
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ProtectHome=true
ReadWritePaths=/opt/mcp-gateway/backend/data
LimitNOFILE=65535

[Install]
WantedBy=multi-user.target
```

```bash
sudo useradd -r -s /usr/sbin/nologin mcpgw
sudo cp -r backend /opt/mcp-gateway/backend && sudo chown -R mcpgw /opt/mcp-gateway
sudo cp backend/.env.example /etc/mcp-gateway.env   # 编辑填入真实密钥，chmod 600
sudo chmod 600 /etc/mcp-gateway.env
sudo systemctl daemon-reload && sudo systemctl enable --now mcp-gateway
sudo journalctl -u mcp-gateway -f                  # 查看日志
```

`main.ts` 已启用 `enableShutdownHooks`，`systemctl stop` 时会触发 `OnModuleDestroy`：审计 flush 落盘、会话排空、上游断连，优雅退出。

## 六、反向代理（Nginx）

`/etc/nginx/conf.d/mcp-gateway.conf`：

```nginx
# 后端上游
upstream mgw_backend { server 127.0.0.1:8080; keepalive 32; }

server {
    listen 443 ssl http2;
    server_name mcp-gw.example.com;

    ssl_certificate     /etc/letsencrypt/live/mcp-gw.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/mcp-gw.example.com/privkey.pem;

    # 前端静态（hash 路由）
    root /var/www/mcp-gateway/dist;
    index index.html;

    # 带 hash 的资源长缓存；index.html 不缓存
    location /assets/ {
        add_header Cache-Control "public, max-age=31536000, immutable";
        try_files $uri =404;
    }
    location / { try_files $uri $uri/ /index.html; add_header Cache-Control "no-cache"; }

    # ── MCP 通道：SSE 长连接，必须关闭缓冲、放大超时 ──
    location /mcp {
        proxy_pass http://mgw_backend;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        proxy_buffering off;              # 关键：SSE 事件流不能被缓冲
        proxy_cache off;
        chunked_transfer_encoding on;
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
    }

    # ── Admin API：建议限内网/办公网 IP ──
    location /admin/api/ {
        # allow 10.0.0.0/8; deny all;      # 按需开启 IP 白名单
        proxy_pass http://mgw_backend;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_buffering off;              # 审计 CSV 导出为流式响应
        client_max_body_size 12m;         # 与后端 json(10mb) 对齐留余量
    }

    # ── 健康/指标：无鉴权，仅放行本机/内网监控 ──
    location ~ ^/(healthz|metrics)$ {
        allow 127.0.0.1;
        allow 10.0.0.0/8;
        deny all;
        proxy_pass http://mgw_backend;
        proxy_set_header Host $host;
    }
}

# HTTP → HTTPS
server { listen 80; server_name mcp-gw.example.com; return 301 https://$host$request_uri; }
```

- 后端已 `trust proxy`，经 Nginx 后仍能从 `X-Forwarded-For` 取到真实客户端 IP，审计 `callerIp` 准确。
- 浏览器端 MCP 客户端跨域时，后端 CORS 已暴露 `Mcp-Session-Id`、`MCP-Protocol-Version`、`Content-Disposition`；如前端与网关不同源，配置 `MGW_ALLOWED_ORIGINS`。

## 七、容器化（Docker / Compose）

`backend/Dockerfile`（多阶段，原生模块只在建阶段编译，运行阶段不含工具链）：

```dockerfile
# ---- build ----
FROM node:20-alpine AS build
WORKDIR /app
RUN apk add --no-cache python3 make g++
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build && npm prune --omit=dev

# ---- runtime ----
FROM node:20-alpine
WORKDIR /app
ENV NODE_ENV=production
COPY --from=build /app/node_modules ./node_modules
COPY --from=build /app/dist ./dist
COPY --from=build /app/package.json ./package.json
COPY config ./config
EXPOSE 8080
USER node
CMD ["node", "dist/main.js"]
```

`docker-compose.yml`（网关 + Nginx 静态/反代）：

```yaml
services:
  gateway:
    build: ./backend
    restart: unless-stopped
    env_file: ./backend/.env
    environment:
      MGW_HOST: 0.0.0.0            # 容器内需监听 0.0.0.0，否则外部不可达
      MGW_DATA_DIR: /data
      MGW_DB_SYNCHRONIZE: "0"
      MGW_SECRET_FILE: /run/secrets/mgw_secret
      ADMIN_TOKEN_FILE: /run/secrets/admin_token
    volumes:
      - mgw-data:/data
    secrets: [mgw_secret, admin_token]

  web:
    image: nginx:alpine
    restart: unless-stopped
    ports: ["443:443", "80:80"]
    volumes:
      - ./frontend/dist:/var/www/mcp-gateway/dist:ro
      - ./deploy/nginx.conf:/etc/nginx/conf.d/mcp-gateway.conf:ro
      - ./deploy/certs:/etc/letsencrypt:ro
    depends_on: [gateway]

volumes:
  mgw-data:

secrets:
  mgw_secret:  { file: ./secrets/mgw_secret.txt }
  admin_token: { file: ./secrets/admin_token.txt }
```

> Compose 网络下，Nginx 的 `upstream` 应指向服务名 `gateway:8080`（而非 `127.0.0.1:8080`）。数据落在命名卷 `mgw-data`，`MGW_DATA_DIR=/data`。

## 八、备份与恢复（SQLite）

网关开启了 WAL，**不要在运行时直接 `cp gateway.db`**（会漏掉 `-wal` 中的最新写入）。用 SQLite 的热备份 API 得到一致快照：

```bash
# 热备份（无需停服），需 sqlite3 CLI
TS=$(date +%F-%H%M%S)
sqlite3 /opt/mcp-gateway/backend/data/gateway.db \
  ".backup '/opt/mcp-gateway/backend/data/backup/gateway-$TS.db'"

# 定时（crontab：每日 02:30）
30 2 * * * sqlite3 /opt/mcp-gateway/backend/data/gateway.db ".backup '/opt/mcp-gateway/backend/data/backup/gateway-$(date +\%F).db'"
```

无 `sqlite3` CLI 时，可在 Node 里用 `better-sqlite3` 的 `db.backup(dest)` 等价实现。备份文件异机/对象存储留存，按合规要求设定保留期。

**恢复**：停服 → 用备份覆盖 `data/gateway.db` 并删除同目录的 `gateway.db-wal`、`gateway.db-shm` → 起服。

## 九、可观测性

| 端点 | 鉴权 | 说明 |
| --- | --- | --- |
| `GET /healthz` | 无 | `{status, uptime_s, registryVersion, tools, sessions, upstreamsConnected, auditQueueDepth, ts}`，用于存活/就绪探针 |
| `GET /metrics` | 无 | JSON 运行指标：`rss_mb, heap_used_mb, uptime_s, registry_version, tools_total, sessions_active, upstreams_connected, ratelimit_buckets, audit_queue_depth, event_loop_lag_ms` |

- **`/metrics` 返回 JSON**（非 Prometheus 文本）。可被 JSON exporter/自研采集器轮询，或用 `json_exporter` 转换后接入 Prometheus。**务必在 Nginx 限制来源**（见上）。
- **事件循环延迟** `event_loop_lag_ms` 是判断网关是否被重负载/大 payload 拖住的关键指标，建议告警阈值 > 100ms。
- **日志**：结构化 JSON 行输出到 stdout，由 systemd journal / Docker logging driver / Loki 收集。
- **告警**：设置 `MGW_IM_WEBHOOK`（企业微信/飞书/Slack）后，熔断开启、上游持续故障等事件会推送到 IM。
- **审计队列深度** `audit_queue_depth` 持续走高说明写盘跟不上，检查磁盘 IO 或调小 `MGW_AUDIT_FLUSH_MS`。

## 十、安全加固清单

- [ ] `MGW_SECRET`、`ADMIN_TOKEN` 均为强随机值，经 `*_FILE`/secret 注入，未写入镜像或仓库
- [ ] `NODE_ENV=production`，`MGW_HOST=127.0.0.1`（容器内 `0.0.0.0` 但不直接对公网暴露端口）
- [ ] `MGW_DB_SYNCHRONIZE=0`，schema 由 migrations 管理
- [ ] 全站 HTTPS，HTTP 强制跳转；HSTS 按需开启
- [ ] `/admin/api`、`/healthz`、`/metrics` 在 Nginx 层限 IP 白名单
- [ ] `MGW_OUTBOUND_ALLOWED_CIDRS` 收敛到实际上游网段（`169.254.0.0/16` 已永久拒绝）
- [ ] 为每类调用方建独立角色/Key，最小权限 + 到期时间；定期轮换（后台一键轮换支持宽限期）
- [ ] 审计日志与变更记录定期导出归档，满足合规留存
- [ ] systemd 沙箱项开启（`ProtectSystem=strict` 等）；容器以非 root `USER node` 运行

## 十一、升级与回滚

```bash
# 升级
cd /opt/mcp-gateway/backend
git pull && npm ci && npm run build
npm run migration:run                     # 若有新迁移
sudo systemctl restart mcp-gateway        # 触发优雅退出钩子

# 前端
cd ../frontend && npm ci && npm run build # 重新生成 dist/，Nginx 无需重启
```

- **回滚**：保留上一个 `dist/` 与数据库备份；回退代码后 `npm run build` 重启，必要时按「八、恢复」回滚数据库。
- 迁移应尽量向后兼容（先加列、双写、再清理），降低回滚风险。

## 十二、故障排查

| 现象 | 可能原因 / 处理 |
| --- | --- |
| 启动即崩，日志报 better-sqlite3 `NODE_MODULE_VERSION` 不匹配 | 原生模块未按当前 Node ABI 编译：`npm rebuild better-sqlite3`，确认 Node ≥ 20.18.1 |
| `SQLITE_BUSY` | 并发写撞锁；已设 `busy_timeout=5000`。若频发，检查是否有备份/外部进程长时间持锁 |
| `/mcp` 返回 401 `Unauthorized` | Bearer Key 错误/过期/已吊销；确认用 MCP Key（`mgw_live_…`）而非 Admin Token |
| 管理后台 401 | `ADMIN_TOKEN` 不匹配，或缺少 `x-admin-user` 头；确认登录填入的 Token 与后端一致 |
| 浏览器 MCP 客户端读不到会话头 / CORS 报错 | 配 `MGW_ALLOWED_ORIGINS`；确认 Nginx 未剥离 `Mcp-Session-Id` 响应头 |
| SSE 事件卡住不推送 | Nginx `proxy_buffering off` 未设或 `proxy_read_timeout` 太短 |
| 新增上游失败，提示出站被拒 | 目标 IP 不在 `MGW_OUTBOUND_ALLOWED_CIDRS`，或落在 `169.254.0.0/16`（永久拒绝） |
| 改了 `MGW_SECRET` 后上游连不上/凭据失效 | 旧凭据用旧密钥加密，无法解密；后台重新录入各上游 Header/Env |
| 报表空白 | 时间范围内无 `tool_call` 审计；或 `days` 选择不当；先确认有真实调用流量 |
| 前端刷新子路由 404 | 用的是 hash 路由（`/#/keys`）不应出现；若改 history 模式需 Nginx `try_files … /index.html` |
